# Генерация агрегированной телеметрии

## Бизнес-описание

Фича позволяет пересобрать компактные файлы телеметрии для графиков из поминутных CSV по скважинам. Это нужно, когда исходная телеметрия обновилась или изменились правила осреднения, а интерфейс должен продолжить быстро открывать скважины без ручной подготовки файлов вне проекта.

На вход подается папка с CSV-файлами скважин. На выходе формируются файлы измерений, сегментированной телеметрии, суточной мощности, суточных средних и событий. Полный пересчет работает в фоне; инкрементальное обновление добавляет только новые строки по времени и пересчитывает затронутые скважины.

В scope входят CSV-файлы с текущим форматом колонок телеметрии. XLSX можно добавлять позднее отдельной веткой, если он станет регулярным источником.

## Описание для агента

Основная точка входа backend: `backend/app/services/telemetry_aggregation.py`.

HTTP API подключено в `backend/app/api/routes/aggregation.py`:

- `POST /api/aggregate` запускает фоновый полный пересчет.
- `POST /api/aggregate/update` принимает `source_folder`, дописывает новые CSV-строки и пересчитывает только затронутые скважины.
- `GET /api/aggregate/status` возвращает состояние фоновой операции из памяти процесса.

Схемы API лежат в `backend/app/schemas/aggregation.py`. Пути берутся из `backend/app/core/config.py`: `telemetry_data_path` и `aggregated_telemetry_data_path`.

Выходные файлы пишутся в `telemetry/aggregated/`: `measurements.csv`, `telemetry.csv`, `power_daily.csv`, `daily_avg.csv`, `events.csv`. Запись идет через временную директорию и копирование в целевой файл. После записи вызывается `clear_timeseries_cache()` из `csv_timeseries.py`, чтобы графики увидели свежие файлы.

Промежуточный результат по каждой скважине сохраняется в `backend/data/_agg_checkpoints/freq_<частота>_tele_<телеметрия>/<well_id>/`. Если процесс был остановлен или упал на финальной записи, следующий запуск переиспользует готовые checkpoints и продолжит без пересчета уже обработанных скважин.

Сегментация телеметрии использует дневные отсечки и начало отклонения от 1-часовой скользящей базы. По умолчанию для частоты ЭЦН применяется порог 5%, для остальных параметров телеметрии - 10%.

## Описание для разработчика

Реализовано:

- фоновые endpoint-ы FastAPI для полного и инкрементального пересчета;
- генерация агрегированных CSV на Polars/NumPy без новых зависимостей;
- атомарная замена выходных файлов через временную папку;
- сброс cache текущего загрузчика графиков после пересчета.

Ключевые файлы: `backend/app/services/telemetry_aggregation.py`, `backend/app/api/routes/aggregation.py`, `backend/app/schemas/aggregation.py`, `backend/app/core/config.py`.

Проверка backend:

```powershell
backend\.venv\Scripts\python.exe -m compileall backend\app
```

Для промышленного переноса стоит отдельно проверить производительность полного пересчета на всех 53 скважинах и добавить управляемый запуск задач вне памяти процесса, если backend будет запускаться в нескольких экземплярах.
