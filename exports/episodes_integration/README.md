# Авторазметка эпизодов работы скважин — пакет для внедрения

Самодостаточный модуль авторазметки + батч-раннер для интеграции в приложение.
Главный принцип: **расчёт офлайн раз в сутки, приложение читает готовые эпизоды**
(никакого пересчёта на лету).

## Поток данных
```
телеметрия (CSV)  ─┐
                   ├─►  compute_episodes.py  ─►  episodes (parquet/CSV/таблица БД)  ─►  API  ─►  UI
прогноз обводн.(CSV)┘        (раз в сутки)        well_id,label,start,end,...,explanation
```

## Файлы
| Файл | Назначение |
|------|------------|
| `episode_rules_v10_1.py` | **Алгоритм** авторазметки. Интерфейс `run_all(tele, vsp) -> DataFrame`. Не менять логику при интеграции. |
| `compute_episodes.py` | **Батч-раннер** (CLI). Точка входа суточного пересчёта: загрузка входов → прогон → атомарная запись. Это и есть то, что планировщик зовёт раз в сутки. |
| `eval_harness.py` | Регрессионный харнесс: сравнение версии с ручной разметкой (precision/recall/F1). Для контроля качества между версиями, в проде не нужен. |
| `docs/input_schema.md` | Какие колонки должна содержать входная телеметрия и файл обводнённости. |
| `docs/output_schema.md` | Схема таблицы `episodes` (что отдаём в API/UI). |
| `docs/codex_prompt.md` | Промпт для Codex — обернуть `compute_episodes.py` в планировщик + хранилище + API. |
| `out/episodes_sample.csv` | Пример выхода (несколько скважин). |

## Запуск суточного пересчёта
```bash
python compute_episodes.py \
    --telem  data/well_graph_data_all_full_<DATE>.csv \
    --wct    data/full_inference_water_cut.csv \
    --out    out/episodes.parquet \
    --model-version episode_rules_v10_1
```
Опции: `--wells Ic_359,Au_389` — посчитать подмножество; `--out *.csv` — писать CSV вместо parquet.

Поведение:
- ошибка по одной скважине логируется и не валит остальные;
- запись **атомарная** (через `*.tmp` + rename) — UI не прочитает полузаписанное;
- в каждую строку проставляются `computed_at` (UTC) и `model_version`.

## Зависимости
`pandas`, `numpy`, `pyarrow` (для parquet). См. `requirements.txt`.

## Версионирование
`model_version` хранится в каждой строке эпизода. При улучшении алгоритма поднимите
`MODEL_VERSION` в `episode_rules_v10_1.py` (или подложите новый модуль), пересчитайте —
старые данные атомарно заменятся. Это позволяет сравнивать версии и откатываться.

## Что НЕ входит в этот пакет
- Прогноз обводнённости (`full_inference_water_cut.csv`) считается отдельной моделью
  (`water_cut_pipeline`); здесь только потребляется как вход `wct_pred`. Категории
  «Рост/Снижение обводнённости» достоверны ровно настолько, насколько точна эта модель.
