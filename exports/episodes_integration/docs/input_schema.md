# Схема входных данных

## 1. Телеметрия (CSV, аргумент `--telem`)
Одна строка = один отсчёт телеметрии. Алгоритм агрегирует до суток сам.
Ключи: `well_id`, `telemetry_time` (datetime).

### Обязательные колонки
| Колонка | Смысл | Используется в |
|---|---|---|
| `well_id` | ID скважины | группировка |
| `telemetry_time` | время отсчёта (datetime) | индекс времени |
| `telemetry_esp_frequency` | частота вращения ЭЦН, Гц | Работа/Остановка, УВЧ, УМЧ, РПТЧ, Периодическая |
| `telemetry_intake_pressure` | давление на приёме (Рпр), бар | Снижение/Рост Рпл, НУР, Деоптимизация, Деградация (fallback) |
| `telemetry_load` | загрузка ЭЦН, % | Деградация ЭЦН |
| `telemetry_qliq` | дебит жидкости (замер), м³/сут | Деградация, Деоптимизация, подтверждение Снижения Кпрод |
| `telemetry_gas_liquid_factor` | газожидкостной фактор (ГЖФ) | ВГФ, Рост/Снижение ГФ |
| `telemetry_bdpv_volume_rate` | объёмный расход БДПВ | СППВ |
| `vsp_status`, `vsp_start_time`, `vsp_end_time` | режимы ВСП ("\|"-разделённые строки) | Остановка/Работа, маска остановок |
| `esp_id` | ID установленного ЭЦН | разрезание на смене насоса |
| `tr_reservoir_pressure` | пластовое давление Рпл (техрежим) | расчёт Кпрод (единственное место, где TR допустим) |
| `tr_liquid_rate` | дебит жидкости (техрежим) | расчёт Кпрод |
| `opz_ids` | ID обработок ПЗ (ОПЗ) | кластеры ОПЗ → уверенность Снижения Кпрод |

### Желательные (повышают качество, не обязательны)
`telemetry_buffer_pressure`, `telemetry_casing_pressure`, `telemetry_water_cut`,
`event_opz`, `days_since_opz`.

> Лишние колонки игнорируются. Отсутствие необязательной колонки → соответствующий
> сигнал просто не используется (категория может не сработать), без ошибки.

## 2. Прогноз обводнённости (CSV, аргумент `--wct`)
Суточный прогноз soft-sensor обводнённости. Подмешивается в телеметрию по `(well_id, дата)`
как колонка `wct_pred`.

| Колонка | Смысл |
|---|---|
| `well` | ID скважины (мапится на `well_id`) |
| `date` | сутки (date) |
| `wct_pred` | прогноз обводнённости, % (доля воды в жидкости) |

Если файл не передан — категории «Рост/Снижение обводнённости» будут пустыми (без ошибки).

## Подготовка (делает `compute_episodes.py` автоматически)
1. Парсинг `vsp_*` "\|"-строк в таблицу интервалов (`build_vsp`).
2. Merge `wct_pred` по `(well_id, floor(telemetry_time))`.
3. Прогон `run_all` по каждой скважине.


## Совместимость с форматом выгрузки приложения
Свежая выгрузка `well_graph_data_<well>_2026-06-21*.csv` — **супер-набор** нужных колонок:
все обязательные поля присутствуют, плюс `telemetry_water_cut_hal`, слоты `target_*`,
`auto_target_*`, `auto_episode_*`, поля ревью. Алгоритм работает с ней **без изменений** —
лишние колонки игнорируются, `auto_*`/`target_*` не используются на входе (это выходные слоты).
