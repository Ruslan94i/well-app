# Схема выхода — таблица `episodes`

Одна строка = один эпизод авторазметки. Это то, что хранится и отдаётся в API/UI.

| Колонка | Тип | Смысл |
|---|---|---|
| `well_id` | string | ID скважины |
| `label` | string | категория эпизода (см. список ниже) |
| `start` | timestamp | начало интервала |
| `end` | timestamp | конец интервала |
| `dur_d` | float | длительность, сут |
| `confidence` | float [0..1] | числовая уверенность |
| `confidence_tier` | string | `high` / `medium` / `low` |
| `sig_label` | string | метка сигнатурного слоя (для НУР/Снижение Рпл; иначе пусто) |
| `sig_margin` | float | запас сигнатуры (иначе пусто) |
| `signals` | string(JSON-подобный) | технические сигналы детектора (для отладки) |
| `explanation` | string | **готовое объяснение в 1 предложение** — показывать в UI по клику |
| `computed_at` | timestamp(UTC) | когда посчитано (метка версии данных) |
| `model_version` | string | версия алгоритма (напр. `episode_rules_v10_1`) |

### Рекомендуемые индексы
`(well_id, start)`, опц. `(well_id, label)`.

### Категории `label` (20)
Работа, Остановка, ГДИ, РПТЧ, УВЧ, УМЧ, НУР, Периодическая работа,
Снижение Рпл, Рост Рпл, Снижение Кпрод, Рост Кпрод, Осложнённый фонд,
Деградация ЭЦН, Деоптимизация, ВГФ, Рост ГФ, Снижение ГФ,
Рост обводненности, Снижение обводненности, СППВ.

> Если набор категорий может расширяться — UI должен строить легенду/цвета
> динамически из данных, а не хардкодом, чтобы новые категории не требовали правок фронта.

### Контракт
Набор и порядок колонок стабилен. Внутренняя логика детекторов может меняться между
версиями — приложение зависит только от этой схемы.


## Запись результата в формат приложения (auto_target_* / auto_episode_*)
Свежий формат выгрузки (`well_graph_data_<well>_*.csv`) содержит **слоты для авторазметки**,
которые заполняет наш алгоритм:
- `auto_episode_*` (id, labels, start, end, confidences) — **поэпизодно**: это ровно таблица
  `episodes` (см. выше). Маппинг: `auto_episode_labels`=`label`, `..._start/end_dates`=`start/end`,
  `auto_episode_confidences`=`confidence`/`confidence_tier`.
- `auto_target_*` — **построчные** дневные флаги (зеркало ручных `target_*`, та же кодировка).
  Заполняются опцией `compute_episodes.py --enrich <out>` (строка получает значение, если её
  `telemetry_time` попадает в интервал эпизода соответствующей категории).

Маппинг метка → `auto_target_*` (значение):
| Метка | Колонка | Значение |
|---|---|---|
| Работа / Остановка | `auto_target_well_state` | `work` / `stop` |
| ГДИ | `auto_target_gdi` | `1.0` |
| УВЧ / УМЧ | `auto_target_uvch` / `auto_target_umch` | `1.0` |
| РПТЧ | `auto_target_rptch` | `1.0` |
| Периодическая работа | `auto_target_periodic` | `1.0` |
| НУР | `auto_target_nur` | `1.0` |
| Снижение / Рост Рпл | `auto_target_rpl_trend` | `falling` / `rising` |
| Деградация ЭЦН | `auto_target_esp_degradation` | `1.0` |
| Рост / Снижение обводненности | `auto_target_wct_trend` | `growing` / `falling` |
| Снижение / Рост Кпрод | `auto_target_kprod_trend` | `declining` / `rising` |
| Осложнённый фонд | `auto_target_complicated_fund` | `1.0` |
| СППВ | `auto_target_sppv` | `1.0` |
| ВГФ | `auto_target_vgf` | `1.0` |
| Рост / Снижение ГФ | `auto_target_gas_factor_trend` | `rising` / `falling` |
| Деоптимизация | `auto_target_deoptimization` | `1.0` |

> `explanation` — отдельная колонка в `episodes`; для построчного экспорта берётся из
> соответствующего эпизода (по перекрытию интервала).


## Расчётный Кпрод для графика (линия «Кпрод_алгоритм»)
Дополнительный суточный ряд расчётного Кпрод (продуктивность = Qж/(Рпл−Рзаб)). Формируется
теми же командами:
- `compute_episodes.py --kprod <out>` → отдельный файл `well_id, date, kprod_calc` (по аналогии с
  прогнозом обводнённости — приложение мёржит по (well_id, дата) и рисует линией);
- `--enrich <out>` → добавляет колонку `kprod_calc` прямо в построчную телеметрию.
Это единственное место, где используется TR (пластовое Рпл) — для самого Кпрод. На график
выводится как ещё одна линия (своя ось), наряду с Обв_алгоритм.


## Слот объяснений auto_episode_explanations (фикс «объяснения = -»)
Команда compute_episodes.py --enrich <out> дополнительно формирует построчную колонку
auto_episode_explanations — «|»-склейка объяснений эпизодов, перекрывающих сутки строки,
В ТОМ ЖЕ ПОРЯДКЕ, что и auto_episode_labels (i-е объяснение соответствует i-й метке).
Используйте её, если UI строит эпизоды из построчных auto_episode_*. Иначе берите колонку
explanation из таблицы episodes по ключу (well_id, label, start).
