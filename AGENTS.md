# AGENTS.md

Инструкции для AI-агентов, работающих с этим прототипом Well App. Перед любыми правками прочитай этот файл и затем изучи затрагиваемые файлы проекта.

Документ лежит в корне репозитория и действует на весь проект, если внутри подкаталогов не появится свой `AGENTS.md`.

## Назначение проекта

Well App - прототип интерфейса для анализа временных рядов по скважинам, разметки эпизодов и режимов, работы с установленными ЭЦН и сохранения пользовательской разметки.

Главный пользовательский сценарий: открыть скважину, посмотреть график телеметрии, работать с частотными отсечками, выделять интервалы, классифицировать эпизоды/режимы и не потерять разметку после перезапуска.

## Текущий стек

- Backend: FastAPI, Uvicorn, Pydantic Settings, Polars, NumPy.
- Frontend: Vue 3, Vite, TypeScript, Tailwind CSS, Naive UI, Plotly.
- Docker Compose: режим запуска backend + frontend в контейнерах.
- Локальный режим: backend из `backend/.venv`, frontend через `npm run dev`.

Важно: этот проект уже создан. Не применяй шаблон нового проекта механически, если он конфликтует с текущей структурой.

## Проверка окружения

Перед установкой зависимостей, запуском или большой задачей проверь инструменты:

- `git --version`
- `docker compose version`
- `node --version`
- `npm --version`
- `python --version` или `backend\.venv\Scripts\python.exe --version`

Для локальной разработки обязательны Git и Docker как базовые инструменты проекта. Python, Node.js и npm нужны для быстрого локального режима.

Если чего-то нет, не устанавливай глобальные зависимости молча. Сначала коротко объясни, что отсутствует, и попроси подтверждение на установку или дай точные инструкции.

## Режимы запуска

При создании нового проекта агент должен спросить режим запуска. Для этого существующего проекта поддерживай оба режима.

### Docker

Используй, когда нужна воспроизводимость и изоляция:

```bash
docker compose up --build
```

Порты задаются в `.env` на основе `.env.example`:

```env
BACKEND_PORT=8000
FRONTEND_PORT=5173
VITE_USE_MOCK_TELEMETRY=true
VITE_USE_MOCK_EVENTS=true
```

### Локально

Используй для быстрой разработки, когда зависимости уже установлены:

```bash
bash run-dev.sh
```

Или вручную:

```bash
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

```bash
cd frontend
npm run dev
```

Frontend обычно доступен на `http://localhost:5173`.

## Структура проекта

- `backend/app/` - FastAPI-приложение.
- `backend/data/` - локальные данные и сохраненная разметка. Не удалять без явной просьбы пользователя.
- `frontend/src/components/` - переиспользуемые компоненты, включая график.
- `frontend/src/views/` - основные экраны.
- `frontend/src/services/` - API и мок-данные.
- `frontend/src/types/` - TypeScript-типы предметной области.
- `project-private/` - локальные приватные настройки, не коммитить.

## Правила разработки

- Сначала читай код вокруг места изменения, затем правь.
- Держи diff минимальным и не делай попутных рефакторингов.
- Не удаляй пользовательские данные, разметку, телеметрию и файлы в `backend/data/` без прямого запроса.
- Не трогай `.env`, `.env.local`, `project-private/`, секреты и локальные логи.
- Frontend должен оставаться рабочим первым экраном, без перехода в маркетинговую посадочную страницу.
- Для графика береги существующие сценарии: масштабирование по X, кнопки прокрутки, hover-линия, выбор частотных промежутков, ручные отсечки, сохранение эпизодов и режимов.
- Если меняешь сохранение разметки, обязательно проверь, что данные не исчезают после перезапуска backend/frontend.
- Не добавляй новые крупные библиотеки без необходимости и без объяснения причины.

## Проверки перед завершением

Для frontend-изменений:

```bash
cd frontend
npm run build
```

Для backend-изменений:

```bash
backend\.venv\Scripts\python.exe -m compileall backend\app
```

Для проверки, что UI жив:

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:5173/ | Select-Object -ExpandProperty StatusCode
```

Если проверку не удалось выполнить, явно скажи почему.

## Git

- Перед началом и перед финальным ответом смотри `git status --short --branch`.
- В рабочем дереве могут быть изменения пользователя или предыдущих задач. Не откатывай их без прямой просьбы.
- Коммить только релевантные файлы. Не добавляй `.env`, `node_modules`, `dist`, `.venv`, логи и приватные файлы.
- Локальный коммит делай после завершенной задачи, если пользователь просит закоммитить или это явно входит в текущую договоренность.
- `git push` выполняй только по явной просьбе пользователя.
